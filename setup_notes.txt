######## To check in the generated code

lwIP
  MEMP_NUM_TCP_PCB            opt.h
  (default is 5, controlling the number of simultaneously active/non-listening TCP connections)
  
  Post-generation manual edit: after CubeMX generates code,
  open Middlewares/Third_Party/LwIP/src/include/lwip/lwipopts.h directly
  and add #define MEMP_NUM_TCP_PCB 8 (or whatever value you want) yourself.
  This survives as long as you don't let CubeMX fully regenerate over your manual edits without preserving user code sections — CubeMX normally respects /* USER CODE BEGIN */ blocks, but lwipopts.h's structure means a full GUI-driven regen can overwrite manual additions outside those blocks, so treat this as something to re-check after any future CubeMX regeneration.
Leave it at 5 for now. Realistically: 1 connection for your MQTT client, leaving 4 free for concurrent web server clients — that's probably fine for a single-device sensor/control node being browsed from a couple of devices on a home network. Not worth chasing until you actually see connection-refused behavior under real testing.
